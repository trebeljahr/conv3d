conv3d is designed to be safe to call from CI pipelines, build scripts, and AI coding agents. This page is the contract.

## Programmatic use

conv3d ships as a CLI only — there is no `import "conv3d"` API. The supported integration surface is **`--json` for machine-readable output, `--yes` for non-interactive runs, and the `0` / `1` / `2` exit codes** — everything below documents that contract.

## The seven rules

1. **Always pass `-y` (or `--non-interactive`)** so no prompt can block. Non-interactive mode is also inferred automatically when stdin is not a TTY.
2. **Explicitly pass `--tsx` / `--no-tsx` and `--optimize` / `--no-optimize`** — in non-interactive mode the defaults are `--tsx --optimize`, but being explicit means your script doesn't care which version of conv3d is installed.
3. **For `bulk`, pass `-m`** in directory mode (`FBX` / `OBJ` / `GLTF` / `ALL`). In glob mode, `-m ALL` is the default.
4. **Pass `--json`** to get a single, machine-readable result object on stdout.
5. **Pass `--dry-run`** first to preview what would be written without touching disk.
6. **Check the exit code.** `0` = success, `1` = fatal, `2` = partial (some files failed — read `errors[]`).
7. **Know the output layout** — or pass `-o`, `--flat`, or the `--*-dir` flags for full control. See [Output layout](./output).

## A minimal agent invocation

```bash
conv3d bulk ./models -m ALL --tsx --optimize -y --json
```

That's it. Stdout is a single JSON object; stderr has any human-readable errors; the exit code tells you whether to proceed.

On a **fatal** error (bad args, missing input):

```jsonc
{ "command": "...", "ok": false, "error": "human-readable message" }
```

…and the process exits `1`.

On a **partial** success (some files converted, some failed), the exit code is `2` and `errors[]` is non-empty.

## Exit codes

| Code | Meaning | When to retry |
|---|---|---|
| `0` | Everything worked. Empty `converted[]` is still `0` if the glob matched nothing (intentional — empty agent globs shouldn't be errors). | Never. |
| `1` | Fatal: bad arguments, missing input directory, unsupported model type. | After fixing the args. |
| `2` | Per-file failures. `converted[]` has the successes, `errors[]` has the failures. | Selectively, only the entries in `errors[]`. |

## stdout vs stderr

- **Stdout** carries the result.
  - In normal mode: human-readable progress lines.
  - In `--json` / `--quiet` mode: either empty or a single JSON object. **Nothing else.**
- **Stderr** carries warnings, errors, and the ASCII banner.

This means you can safely do:

```bash
conv3d bulk ./models -m ALL --tsx -y --json | jq '.converted[]'
```

…and `jq` will only ever see the JSON object.

The ASCII banner is suppressed automatically when stdout is not a TTY, or when `--help` / `--version` / `--quiet` / `--json` is passed — agents will never see it.

## Recipes

A few patterns that come up in agent flows. For the broader catalogue — including non-agent invocations — see [Recipes](./recipes).

### Convert and pipe paths to another tool

```bash
conv3d bulk ./models -m ALL --tsx -y --json \
  | jq -r '.converted[]' \
  | xargs -I {} my-thumbnail-tool {}
```

### Verify install health before running

```bash
if ! conv3d doctor --json | jq -e '.dependencies | all(.installed != null)' >/dev/null; then
  echo "conv3d install is incomplete" >&2
  exit 1
fi
```

### Idempotent re-run

```bash
conv3d bulk ./models -m ALL --tsx --optimize -y -f --json
# -f replaces existing outputs; safe to run on every build
```

### Quietly skip already-converted files

```bash
conv3d bulk ./models -m ALL --tsx --optimize -y --overwrite=skip --json
# .skipped[] in the result tells you which were untouched
```

### Preview a destructive change

```bash
conv3d bulk ./models -m ALL --tsx --optimize --dry-run --json \
  | jq '.converted, .tsx, .glbOptimized'
```

`--dry-run` never creates files — not even the output directories.

### Parse partial success

```bash
result=$(conv3d bulk ./models -m ALL --tsx -y --json) || true
echo "$result" | jq '.errors[] | "FAILED: \(.file) — \(.message)"'
echo "$result" | jq '.converted | length' # how many succeeded
```

## Notes for agents

- **Pass `-y` even when calling `single`** — it never prompts then, no matter what.
- **`single` returns `inputPath`, not `inputDir`** in its JSON. Watch for that.
- **`tsx-gen` doesn't care about the input format flag** — it always operates on `.glb`.
- **`doctor` always exits `0`** — even when dependencies are missing. Inspect `.dependencies[].installed` for the actual state.
- **File-exists conflicts default to `skip`** in non-interactive mode. Pass `--overwrite=replace` (or `-f`) when you want idempotent reruns.
- **`--dry-run` never writes** — not even the output directory tree.
- **`figlet` and `lolcatjs` are optional**. `npm install --omit=optional` still gives you a working CLI, just without the rainbow banner.

## Tool definitions for AI coding agents

These snippets define one narrow tool: bulk-convert models through the CLI, returning conv3d's JSON result. Keep `dryRun` enabled for the first call, inspect the planned `converted`, `tsx`, `glbOptimized`, `skipped`, and `errors` arrays, then call the same tool with `dryRun: false` only when the plan is correct.

The implementation behind each schema should build the command from the arguments, never from a free-form shell string:

```bash
conv3d bulk "$input" -m "$modelType" --yes --json --dry-run
```

Add the optional flags requested by the arguments (`--recursive`, `--tsx` / `--no-tsx`, `--optimize` / `--no-optimize`, `--overwrite`, `--outputDir`, `--flat`, `--glb-dir`, `--tsx-dir`, `--optimized-dir`, `--concurrency`, `--resolution`, `--keep-materials`). When `dryRun` is `false`, omit only `--dry-run`; keep `--yes` and `--json`.

### Handler sketch

This is the command builder each MCP or SDK wrapper should use. It avoids shell interpolation, so glob strings and paths stay data, not executable code.

```ts
import { spawn } from "node:child_process";

type Conv3dBulkArgs = {
  input: string;
  modelType: "GLTF" | "FBX" | "OBJ" | "ALL";
  recursive?: boolean;
  tsx: boolean;
  optimize: boolean;
  outputDir?: string;
  flat?: boolean;
  glbDir?: string;
  tsxDir?: string;
  optimizedDir?: string;
  overwrite?: "skip" | "replace" | "ask";
  concurrency?: number;
  resolution?: number;
  keepMaterials?: boolean;
  dryRun?: boolean;
};

export function buildConv3dBulkArgs(args: Conv3dBulkArgs): string[] {
  const command = ["bulk", args.input, "-m", args.modelType, "--yes", "--json"];

  if (args.recursive) command.push("--recursive");
  command.push(args.tsx ? "--tsx" : "--no-tsx");
  command.push(args.optimize ? "--optimize" : "--no-optimize");
  if (args.outputDir) command.push("--outputDir", args.outputDir);
  if (args.flat) command.push("--flat");
  if (args.glbDir) command.push("--glb-dir", args.glbDir);
  if (args.tsxDir) command.push("--tsx-dir", args.tsxDir);
  if (args.optimizedDir) command.push("--optimized-dir", args.optimizedDir);
  if (args.overwrite) command.push("--overwrite", args.overwrite);
  if (args.concurrency) command.push("--concurrency", String(args.concurrency));
  if (args.resolution) command.push("--resolution", String(args.resolution));
  if (args.keepMaterials) command.push("--keep-materials");
  if (args.dryRun !== false) command.push("--dry-run");

  return command;
}

export async function runConv3dBulk(args: Conv3dBulkArgs) {
  const child = spawn("conv3d", buildConv3dBulkArgs(args), {
    stdio: ["ignore", "pipe", "pipe"]
  });

  const stdout: Buffer[] = [];
  const stderr: Buffer[] = [];
  child.stdout.on("data", (chunk) => stdout.push(chunk));
  child.stderr.on("data", (chunk) => stderr.push(chunk));

  const exitCode = await new Promise<number>((resolve) => {
    child.on("close", (code) => resolve(code ?? 1));
  });

  return {
    exitCode,
    result: JSON.parse(Buffer.concat(stdout).toString("utf8")),
    stderr: Buffer.concat(stderr).toString("utf8")
  };
}
```

### Worked dry-run then execute transcript

An agent should make the dry-run explicit in its first call:

```json
{
  "tool": "conv3d_bulk",
  "arguments": {
    "input": "./raw-assets/characters",
    "modelType": "FBX",
    "recursive": true,
    "tsx": true,
    "optimize": true,
    "outputDir": "./public/models",
    "flat": true,
    "overwrite": "skip",
    "dryRun": true
  }
}
```

The wrapper runs:

```bash
conv3d bulk ./raw-assets/characters -m FBX --yes --json --recursive --tsx --optimize --outputDir ./public/models --flat --overwrite skip --dry-run
```

The tool returns the parsed JSON and exit code:

```json
{
  "exitCode": 0,
  "result": {
    "command": "bulk",
    "ok": true,
    "inputDir": "/repo/raw-assets/characters",
    "outputDir": "/repo/public/models",
    "dryRun": true,
    "modelType": "FBX",
    "converted": [
      "/repo/public/models/Knight.glb",
      "/repo/public/models/Wizard.glb"
    ],
    "tsx": [
      "/repo/public/models/Knight.tsx",
      "/repo/public/models/Wizard.tsx"
    ],
    "glbOptimized": [
      "/repo/public/models/Knight-transformed.glb",
      "/repo/public/models/Wizard-transformed.glb"
    ],
    "skipped": [],
    "errors": []
  },
  "stderr": ""
}
```


```bash
conv3d bulk ./raw-assets/characters -m FBX --yes --json --recursive --tsx --optimize --outputDir ./public/models --flat --overwrite skip
```
